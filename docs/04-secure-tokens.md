# Secure Tokens

Secure tokens let you **personalize campaigns with user data** — pre-filling known fields
or identifying the participant — in a way that cannot be tampered with by the client. A
token is a signed JWT generated by your backend and attached to the campaign.

On iOS, secure tokens are provided through the **`QualifioDelegate`**. When a delegate is
set, the SDK asks it for a token every time a campaign is launched and appends the returned
token to the campaign URL as the `qual_token` query parameter.

## Setting the delegate

Assign an object that conforms to `QualifioDelegate` to `Qualifio.shared.delegate`, then
implement the secure-token method:

```swift
import QualifioKit

Qualifio.shared.delegate = self
```

```swift
extension MyCoordinator: QualifioDelegate {
    func qualifio(_ qualifio: Qualifio, generateSecureTokenFor url: URL) async throws -> String? {
        // Ask your backend to mint a signed token for the current user.
        return try await backend.mintToken(for: url) // a String, or nil to launch without a token
    }
}
```

> The delegate is held **weakly**, so keep a strong reference to the object you assign (for
> example your app delegate or a long-lived coordinator). The same delegate is also used to
> [customize the Safari view controller](./06-customizations.md).

### The secure-token method

| Aspect | Details |
|--------|---------|
| Argument | `url` — the campaign URL about to be opened. |
| Returns | The token `String`, or `nil` to launch without a token. |

- Return a **`String`** to attach it to the campaign as `qual_token`.
- Return **`nil`** to launch the campaign without a token.

Because the method is `async throws`, you can perform asynchronous work (such as a network
request) to mint the token.

### Completion-handler variant

If you prefer not to use `async`/`await`, implement the completion-handler overload instead.
It delivers its result through a `QualifioCallback`:

```swift
func qualifio(
    _ qualifio: Qualifio,
    generateSecureTokenFor url: URL,
    _ completion: @escaping QualifioCallback<String?>
) {
    backend.mintToken(for: url) { result in
        completion(result) // Result<String?, Error>
    }
}
```

`QualifioCallback` is defined as:

```swift
public typealias QualifioCallback<T> = (Result<T, Error>) -> Void
```

Implement **either** the `async` method or the completion-handler method — the SDK provides
default implementations that bridge between the two.

## When and how the token is applied

Each time you call [`launchCampaign`](./03-campaigns.md), the SDK:

1. Asks the delegate for a token for the campaign URL.
2. If a non-`nil` token is returned, appends it to the campaign URL as `?qual_token=<token>`.
3. Opens the campaign in the Safari view controller.

## Error handling

If your delegate **throws** (or its result is `nil`), the SDK logs the problem and launches
the campaign **without** a token. This means a transient token-service failure degrades
gracefully rather than blocking the user.

## Security best practices

- **Generate tokens on your server**, never on the device. The signing secret must never be
  embedded in your app.
- **Keep tokens short-lived.** Mint them on demand so each launch uses a fresh token.
- **Scope tokens** to the current user (and campaign, if applicable).
